# PetClinic REST API — автотесты на Go

API-тесты для [Spring PetClinic REST](https://github.com/spring-petclinic/spring-petclinic-rest):
владельцы, поиск и список, питомцы, негативные проверки. Нужен Go 1.22+.

## Запуск тестируемого сервиса

```
docker run --rm -p 9966:9966 springcommunity/spring-petclinic-rest
```

Сервис готов, когда отвечает `http://localhost:9966/petclinic/api/pettypes`. Авторизация не нужна,
база H2 в памяти — `docker restart` возвращает её в исходное состояние.

## Установка зависимостей и запуск

```
go mod download
go test ./tests -count=1 -v
```

## Отдельные группы проверок

```
go test ./tests -run TestOwnersCRUD -count=1 -v
go test ./tests -run TestOwnersList -count=1 -v
go test ./tests -run TestPets -count=1 -v
go test ./tests -run TestNegative -count=1 -v
```

## Адрес тестируемого сервиса

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PETCLINIC_BASE_URL` | базовый URL API | `http://localhost:9966/petclinic/api` |
| `PETCLINIC_TIMEOUT` | таймаут HTTP-клиента | `10s` |

PowerShell:

```
$env:PETCLINIC_BASE_URL="http://stand:9966/petclinic/api"
go test ./tests -count=1
```

bash:

```
PETCLINIC_BASE_URL=http://stand:9966/petclinic/api go test ./tests -count=1
```

## Структура

```
config/            базовый URL и таймаут из окружения
internal/
  models/          типизированные запросы и ответы
  client/          HTTP-клиент: модель + сырой ответ
  checkers/        переиспользуемые проверки
  fixtures/        генерация данных и уборка
tests/             сценарии, по файлу на группу
```

Клиент возвращает и модель, и сырой ответ: на 204 и 404 тела нет, проверять можно только по статусу.

## Что проверяется

- `owners_crud_test.go` — создать владельца, получить по id, обновить, удалить и убедиться,
  что после удаления он отдаётся как 404.
- `owners_list_test.go` — поиск по фамилии находит ровно созданного владельца, он же есть в общем
  списке; отдельно зафиксирована семантика фильтра.
- `pets_test.go` — питомец добавляется существующему владельцу, сверяются имя, дата рождения,
  тип и связь через `ownerId`.
- `negative_test.go` — запросы к несуществующим объектам и некорректные тела с разбором по полям.

Объём держится в рамках четырёх групп из задания. Визиты, ветеринары, специальности и пользователи
в объект тестирования не входят и не покрываются.

## Как проверялся контракт

Перед написанием тестов API был пройден руками. Результаты лежат в `mtx.xlsx` в корне репозитория:
по строке на проверку, с ожидаемым кодом, телом ответа и ссылкой на тест, который её закрывает.

Сервис отдаёт встроенный Swagger UI, поднимать отдельно ничего не нужно:

```
http://localhost:9966/petclinic/swagger-ui.html
```


Спеку сервис отдаёт сам — OpenAPI 3.1, 19 ручек:

```
http://localhost:9966/petclinic/v3/api-docs
```

Её можно импортировать в Postman через Import и ссылку. Генерится она не мгновенно, на первый
запрос уходит несколько секунд. Если сервис спеку не отдал — она лежит в его репозитории,
`src/main/resources/openapi.yml`.

## Особенности контракта

Проверено на живом сервисе, часть поведения расходится с openapi — ожидания выставлены по факту.

- `PUT` отвечает **204 без тела**, поэтому результат обновления сверяется следующим `GET`.
- `404` «объект не найден» приходит **с пустым телом**, без ProblemDetail. Разбирать тело ошибки
  имеет смысл только на 400 и на 404 от несуществующего типа питомца.
- Поиск по `lastName` идёт **по префиксу и с учётом регистра**, а если совпадений нет — приходит
  **404**, а не пустой массив.
- Тип питомца передаётся **вложенным объектом** `type: {id, name}`; плоский `typeId` отклоняется с 400.
- Валидация: `firstName` и `lastName` только из букв, до 30 символов; `telephone` — ровно 10 цифр.
- Синтаксически битый JSON даёт **500**, а не 400.

## Данные и независимость

Каждый тест создаёт всё, что ему нужно, и не опирается на сидовые записи. Фамилия владельца
генерируется уникальной, поэтому поиск находит только свою запись.

Уборка идёт в `TearDownSuite` и отрабатывает даже после падения теста. **Питомцы удаляются раньше
владельцев** — это важно: удаление владельца каскадом уносит не только его питомцев, но и их тип
из справочника `/pettypes`. Если удалять владельца первым, справочник деградирует от прогона
к прогону и тесты начинают падать без видимой причины. `404` при уборке считается нормой:
объект мог быть удалён самим сценарием.
